# รายงานตรวจการเข้าถึง · A2

ตรวจเมื่อ 2026-09-08 จากเซิร์ฟเวอร์ `http://127.0.0.1:8799` ด้วย Playwright Chromium · viewport 390×844 และ 1440×844 · หน้าที่ตรวจ: `/`, `/places/`, `/places/tao-ming/`, `/stories/city/`, `/map/`, `/trip/`

## 1) alt ของรูปภาพ

**ตรวจแล้วไม่พบปัญหา** · ตรวจ DOM `img` ทุกตัวในทั้ง 6 URL ที่สองขนาดหน้าจอ

- รูปเนื้อหามี alt ที่สื่อความหมาย เช่น `/places/tao-ming/` รูปอาคารใช้ `อาคารโรงเรียนเต้าหมิง ถนนสายวัฒนธรรมเมืองเก่าตะกั่วป่า` และรูปตราใช้ `ตราโรงเรียนเต้าหมิง`
- `/` มีรูปบางตัว alt ว่าง เช่น `riverwalk.webp`, `culture-street.webp`, `iron-bridge.webp`, `food-center.webp`, `tao-ming.webp` · จาก DOM เป็นภาพประกอบในแถบภาพ/การ์ดที่มีข้อความลิงก์กำกับ จึงใช้ alt ว่างได้
- `/map/` และ `/trip/` ไม่มี `img` ใน DOM ที่ตรวจได้

## 2) ปุ่ม/ลิงก์ไอคอนล้วน

**ตรวจแล้วไม่พบปัญหาในชุดควบคุมที่แสดงผล** · ตรวจ `a, button` ที่ไม่มีข้อความในทั้ง 6 URL

หลักฐานจาก DOM ที่พบซ้ำทุกหน้า: `[data-theme-toggle]` มี `aria-label="สลับเป็นโหมดกลางคืน"`, `[data-nav-toggle]` มี `aria-label="เปิดเมนู"`, และ `[data-open-search]` มี `aria-label="ค้นหาในเว็บไซต์ (กด Ctrl+K)"` · glyph ภายในถูกกำหนด `aria-hidden="true"`

## 3) contrast · โหมดสว่าง/กลางคืน

**พบปัญหา · ความรุนแรง: ควรแก้**

- สีข้อความรอง `rgb(95, 106, 91)` บนพื้นหลังโทนครีมของหน้าเว็บคำนวณได้ประมาณ 3.7:1 · ไม่ผ่าน WCAG AA สำหรับข้อความปกติ (พบใน breadcrumb/eyebrow และข้อความขนาดเล็ก เช่น `/`, `/places/`, `/places/tao-ming/`, `/stories/city/`, `/map/`, `/trip/`)
- สี accent `rgb(166, 69, 43)` บนพื้นหลังเดียวกันได้ประมาณ 3.5:1 · ไม่ผ่าน AA สำหรับข้อความปกติเมื่อใช้กับข้อความขนาดเล็ก เช่นหัวข้อ/label บางรายการ

ตรวจการสลับโหมดด้วยการคลิก `[data-theme-toggle]` ที่ทุก URL และตรวจซ้ำใน DOM แล้ว · **ตรวจอัตราส่วน contrast ของโหมดกลางคืนแบบครบทุกคู่ไม่ได้** เพราะสคริปต์/DOM รายงานพื้นหลังของหลายข้อความเป็น `rgba(0, 0, 0, 0)` และไม่ได้ resolve สีพื้นหลังจริงจาก ancestor/ภาพพื้นหลังอย่างถูกต้อง จึงไม่เดาตัวเลขแทนหลักฐาน

## 4) Tab, focus, focus trap, Esc

**ตรวจแล้วไม่พบปัญหา** สำหรับเส้นทางที่ทดสอบ

- กด Tab เดินผ่าน interactive controls ได้ทั้ง 390px และ 1440px · ไม่พบ focus หายหรือวนกลับผิดปกติในรอบที่ตรวจ
- focus ที่ลิงก์ `ข้ามไปเนื้อหา` แสดง outline `rgb(166, 69, 43) solid 3px` ทุกหน้าที่ทดสอบ
- ที่ 390px คลิก `[data-nav-toggle]` แล้วได้ `aria-expanded="true"` และ `#main-nav` แสดงผลเป็น `flex` · กด `Escape` แล้วได้ `aria-expanded="false"` และ `#main-nav` เป็น `display: none` ทั้ง 6 URL
- **ตรวจ focus trap แบบครบทุก modal ไม่ได้** เพราะรอบตรวจนี้ไม่ได้เปิด/ทดสอบ search overlay และองค์ประกอบ interactive ทุกสถานะที่อาจเปิดได้ครบถ้วน

## 5) พื้นที่กดบนมือถือ

**พบปัญหา · ความรุนแรง: ควรแก้** · ที่ viewport 390px ตรวจ bounding box ของ `a, button, [role=button], input, select, textarea`

- เมนูนำทางด้านบนหลายรายการสูง `41px` เช่น `สถานที่`, `เรื่องเล่า`, `แผนที่`, `กินเที่ยว`, `ความเคลื่อนไหว`, `ทริปของคุณ` · ต่ำกว่าเกณฑ์ 44×44px ในแกนความสูง
- ปุ่มสลับธีมมีขนาด `42×42px` · ต่ำกว่า 44×44px ทั้งสองแกน
- ลิงก์เมนูที่ถูกซ่อนมีขนาด `0×0px` แต่ไม่ใช่พื้นที่กดที่ผู้ใช้มองเห็น จึงไม่จัดเป็นปัญหาพื้นที่กด
- ไม่พบปัญหาเดียวกันจากขนาด 1440px ที่เป็น desktop layout ในชุดรายการที่มองเห็น

## สรุป

พบ 2 กลุ่มปัญหาที่มีหลักฐาน: contrast ของข้อความสีรอง/accent ขนาดเล็ก และ touch target ของเมนู/ปุ่มธีมบนมือถือ · ไม่แก้ไฟล์อื่นตามข้อกำหนดงาน · รายการที่ตรวจไม่ได้ระบุเหตุผลไว้ในหัวข้อที่เกี่ยวข้องแล้ว
