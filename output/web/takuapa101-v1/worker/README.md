# ระบบข่าวอัตโนมัติ · takuapa101-news

Cloudflare Worker ที่ดึงข่าวเมืองตะกั่วป่าเอง กรอง ตรวจซ้ำด้วย AI แล้วส่งให้เว็บ
ไม่มีคนกดอนุมัติในขั้นตอนไหนเลย แต่ไม่มีข่าวไหนขึ้นเว็บโดยผ่านแค่ตัวกรองกฎอย่างเดียว

## ข่าวเดินทางยังไง

```
แหล่งข่าว ──► ด่าน 1 กฎ ──► ด่าน 2 AI อ่านซ้ำ ──► KV ──► เว็บ
   279         115 ผ่าน       publish/hold/drop      live/held    ต่อท้ายข่าวเดิม
```

**ด่าน 1 · ตัวกรองกฎ** (`src/filter.js` · ฟรี ทันที ตัดสินแน่นอน)
1. ต้องมีคำว่า ตะกั่วป่า / ตะโกลา / กั่วป่าโพ้ / Takua Pa ในหัวข้อหรือเนื้อย่อ
2. ตัดหมวดที่ไม่ใช่ข่าวเมือง: ดัชนีคุณภาพอากาศ · พยากรณ์อากาศ · ประกาศขายที่ดิน · หวย · ราคาทอง · โปรโมชั่น · อาชญากรรมและอุบัติเหตุ
3. สำนักข่าวต้องอยู่ใน `OUTLET_ALLOWLIST` เท่านั้น
4. เดาว่าข่าวนี้เกี่ยวกับสถานที่ไหนจาก `PLACE_KEYWORDS`
5. ให้คะแนนความเกี่ยว 0-100 เพื่อจัดคิวส่งเข้าด่าน 2

**ด่าน 2 · AI อ่านซ้ำ** (`src/recheck.js`)
ส่งข่าวที่ผ่านด่าน 1 ให้โมเดลอ่านแล้วตัดสิน 4 ข้อ: เป็นข่าวตะกั่วป่าจริงไหม ·
คนสนใจเมืองอยากรู้ไหม · ไม่ใช่ข่าวร้ายหรือโฆษณาใช่ไหม · หัวข้อไม่ clickbait ใช่ไหม
ตอบกลับเป็น `publish` / `hold` / `drop` พร้อมคะแนนความมั่นใจ และเรียบเรียงหัวข้อกับสรุปใหม่
จากเนื้อที่ให้ไปเท่านั้น

- `publish` และมั่นใจ `>= MIN_CONFIDENCE` (ค่าเริ่มต้น 75) → ขึ้นเว็บ
- `hold` หรือมั่นใจต่ำ → เข้า `/api/held` ไม่ขึ้นเว็บ
- `drop` → ทิ้ง
- **ถ้าเรียกโมเดลไม่สำเร็จ ข่าวจะถูกจัดเป็น `hold` เสมอ** ข่าวที่ยังไม่ถูกตรวจจะไม่มีทางขึ้นเว็บ

โมเดลที่ใช้: ถ้าตั้ง secret `ANTHROPIC_API_KEY` จะใช้ Claude (ภาษาไทยดีที่สุด)
ถ้าไม่ตั้ง จะใช้ Workers AI ที่มีมาในตัว Cloudflare ไม่ต้องใช้คีย์ภายนอก

## แหล่งข่าว (`src/sources.js`)

| แหล่ง | สถานะ |
|---|---|
| Google News RSS 8 คำค้น | ใช้ได้ทันที ไม่ต้องใช้คีย์ |
| เทศบาลเมืองตะกั่วป่า `takuapacity.go.th` | ใช้ได้ทันที |
| ททท. · กรมศิลปากร | ใช้ได้ทันที |

| เพจ Facebook ท้องถิ่น | ต้องตั้ง secret `FB_TOKEN` และ `FB_PAGES` ก่อน |

## ติดตั้ง

wrangler login ต้องรันในเทอร์มินัลจริง (พิมพ์ `!` นำหน้าคำสั่งได้ในเซสชันนี้)

```powershell
cd D:\Siwaracafeweb\output\web\takuapa101-v1\worker
npx wrangler login
npx wrangler kv namespace create NEWS
npx wrangler kv namespace create NEWS --preview
```

เอา id ที่ได้ไปใส่แทน `REPLACE_WITH_KV_ID` และ `REPLACE_WITH_KV_PREVIEW_ID` ใน `wrangler.toml` แล้ว

```powershell
npx wrangler secret put ANTHROPIC_API_KEY   # ไม่บังคับ ถ้าไม่ใส่จะใช้ Workers AI
npx wrangler secret put RUN_KEY             # กุญแจสำหรับสั่งรันเองผ่าน /api/run
npx wrangler deploy
```

ถ้าจะใช้ Workers AI ให้เพิ่มใน `wrangler.toml`

```toml
[ai]
binding = "AI"
```

## เปิดใช้งานฝั่งเว็บ

```powershell
$env:TAKUAPA_NEWS_API = "https://takuapa101-news.<subdomain>.workers.dev"
python build_site.py
```

ค่านี้จะไปอยู่ที่ `<html data-news-api="...">` แล้ว `site/assets/live-news.js` จะดึงข่าวมาต่อท้ายรายการที่ build ไว้
ถ้า Worker ล่มหรือยังไม่ได้ deploy เว็บจะแสดงข่าว 31 ชิ้นที่ build ไว้ตามปกติ ไม่พัง

## ตรวจสอบ

```
GET /api/news    ข่าวที่ผ่านทั้งสองด่าน (ที่แสดงบนเว็บ)
GET /api/held    ข่าวที่ AI ไม่มั่นใจ ไม่ขึ้นเว็บ ใช้ดูว่าตัวกรองพลาดอะไรไหม
GET /api/status  สถิติการรันครั้งล่าสุด
GET /api/run?key=RUN_KEY   สั่งรันทันทีโดยไม่รอ cron
```

`/api/held` คือที่ที่ควรเปิดดูเป็นระยะ ถ้าเจอข่าวดีตกอยู่ในนั้นบ่อย แปลว่าควรลด `MIN_CONFIDENCE`
ถ้าเจอข่าวไม่ดีหลุดขึ้นเว็บ แปลว่าควรเพิ่ม `MIN_CONFIDENCE` หรือเติม pattern ใน `BLOCK_PATTERNS`

## ทดสอบตัวกรองในเครื่องก่อน deploy

```powershell
node test_filter.mjs
```

ดึงข่าวจริงจาก Google News แล้วแสดงว่าด่าน 1 เก็บอะไรและตัดอะไรออก พร้อมเหตุผล

## ข้อจำกัดที่ควรรู้

ข่าวที่ขึ้นเองจะมีป้าย **"ดึงอัตโนมัติ"** กำกับบนเว็บ เพื่อแยกจากข่าวที่ตรวจด้วยคนแล้ว
AI ที่ตรวจซ้ำลดความผิดพลาดได้มาก แต่ไม่ใช่ศูนย์ · การเปิดดู `/api/news` สัปดาห์ละครั้ง
ยังเป็นวิธีที่ถูกที่สุดในการจับข่าวที่หลุดมา
